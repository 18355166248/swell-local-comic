# Swell Comic 界面与阅读交互设计

本轮以本地漫画桌面阅读为核心，统一书库、目录预览、历史和阅读器的视觉层级。日期：2026-10-23。

## 设计依据

对现有深色产品探索了卡片书库、紧凑列表、侧栏工作台三个方向，选用卡片书库结构。[参考稿](library-reference.png)为布局依据；产品继续使用仓库中的真实应用图标，不把参考稿中的示意图标或示例内容作为生产素材。

书库结构依次为：56px 主导航、页面标题及添加操作、最近阅读、搜索与排序、作品卡片。大窗口三列，中等窗口两列，小窗口一列。每件作品保留独立的目录预览和继续阅读入口；扫描失败显示重试，而非显示零章。

目录页使用轻分割章节行，合并重复概览。搜索、阅读状态、目录/列表、展开项和已加载批次按作品保留。刷新期间保留旧结果，失败后可重试。章节预览只看前三张，不写入阅读进度。

历史页使用一个可搜索、可筛选的列表，避免多层卡片。所有继续阅读入口共享文件校验、会话取消与导航逻辑。

阅读器采用画布优先布局。48px 顶栏保留返回、章节名、阅读设置和窗口控制；280px 设置面板按需展开。分页导航和图片显示操作分别悬浮在画布左右，避免占用上下高度。分页默认铺满可用高度，横向超出的部分可拖动查看；也可切换完整显示或原图大小。图片页览保持模态交互、分组加载和 Esc 关闭。

## 代码结构与约束

- `WindowControls` 复用桌面窗口操作；`AppShell` 只负责主导航与页面容器。
- `useReadingSessionEntry` 管理入口异步生命周期；`readingSession` 刷新文件清单、匹配最深书库、按文件名修正页码。旧请求不得覆盖或清空新会话。
- `useLibraryChapterCounts` 限制扫描并发为 2，并复用 StrictMode 中的任务；浏览状态由 `useLibraryBrowseState` 和纯工具管理。
- `readerImageResources` 统一 Blob URL 所有权、并发 3、请求去重、队列提权和失效代次。首批优先当前页与邻页；旧结果释放后不能重新发布。
- `useReadingHistoryPersistence` 合并高频历史更新；离开、隐藏及跨章前同步保存滚动快照。恢复未完成时保留原进度，明确的滚动输入取消迟到恢复。
- `readerPosition` 以阅读线判定当前图片，并提供可测试的位置上报和恢复调度。

本轮没有引入新的运行时依赖。全章最终仍保留 Blob；当前改善的是首批可读时间、读图并发和生命周期正确性，尚未实现长章的按窗口回收。历史存储格式保持兼容。

## 验证与证据

自动检查：`node --test scripts/*.test.mjs`、`node node_modules/typescript/bin/tsc -b`、源码及测试 ESLint、Vite 生产构建、`git diff --check`。

隔离浏览器使用六部合成作品、每章 30 张测试图片，避免改写桌面实际书库。检查了搜索、刷新保留条件、章节预览/关闭、历史续读、目标页优先、精确像素恢复、早退保存、旧队列取消、模式切换、页览、跳转校验和窄窗口布局。

Tauri 冒烟通过本地 CLI、现有开发配置及临时覆盖启动，使用已运行的 1431 测试服务和项目内独立数据目录；Rust 编译完成，桌面进程创建了 `swell-local-comic` 窗口且响应正常，正常关闭后退出码为 0。此次未进行安装包发布，也未用浏览器模拟结果代替原生窗口启动检查。

视觉比较与逐项结论见项目根目录 [design-qa.md](../../design-qa.md)。
